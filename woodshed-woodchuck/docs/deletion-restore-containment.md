# Containing a restore after an account deletion

An older backup can contain a valid student login, working private links and the original personal data. Restoring only the application code or changing the session secret leaves data in the restored database. Use this procedure for a disaster-recovery or investigation copy.

1. Before opening any backup, assign a named custodian. Record the backup generation, creation/expiry time, source, expected archive checksum, custody location and intended disposable target in the restricted operations register. An archive with unverified origin is ineligible. Treat the working copy, export files and snapshots as personal information.
2. Restore only to a new private instance with no application connection pool, public route, replication subscription, job, mailer or provider credentials. Block inbound and outbound network paths. Install [the PostgreSQL admission policy](../ops/restore-quarantine.pg_hba.conf) before starting the instance. Set `listen_addresses=''`, use a private mode-0700 Unix socket directory and set `unix_socket_permissions=0700`. In `pg_ident.conf` map only the named custodian's OS account to `ww_restore_custodian` in the `woodshed_restore` map. Keep the OS account, directory, HBA, role and backup outside web/worker control.
3. Check the instance identity, socket, HBA and restore destination independently. Verify the custodian can inspect the empty target and both the web and worker logins are denied. Use a known database archive, an explicitly named empty database, and `pg_restore --exit-on-error --no-owner --no-acl`. Keep roles, cluster globals, configuration, and network ACLs under target control. Recheck admission and the effective listener after the restore; stop the target on a failed check. Never use a serving database as the target.
4. This minimum procedure ends in quarantine. An operator can audit the isolated copy. There is no release or promotion step for a data-bearing restore. Keep unverified generations closed, even if a spot check of known deletions passes. Dispose of the restore instance, archive copies and any derivatives within the original backup retention window; record disposal and escalate missed deadlines. A local scratch-directory deletion does not prove destruction of provider snapshots or disk media.
5. For controlled backups the approved maximum is 30 days **from creation**. A restore does not reset it. Inventory all generations and provider copies. Retain minimum independently held deletion/replay evidence for at least seven days after the last capable backup expires. Restrict access and dispose of it under the approved retention schedule. Report any backup with unknown coverage or missing evidence as ineligible.

## Qualification and operational boundary

The synthetic PostgreSQL test archives a live account, deletes it via the authenticated HTTP form, verifies a prior session cannot fetch its data, restores the real archive into a second cluster, and confirms the old active identity and saved state are present. Database admission rejects the web and worker logins both before and after restoration, although those roles exist and have LOGIN. No application, worker or mailer runs against that target. Run this test from the application directory using PostgreSQL tools and a non-root account:

```bash
WW_PLAY_DELETION_PG=1 python -m pytest -q tests/test_deletion_restore_containment.py
```

Managed hosting might not expose HBA files or Unix sockets. An externally isolated instance with separately enforced network and credential barriers would need its own qualification. Until operators verify that containment, disable any automatic failover or restore-to-serving path capable of exposing pre-deletion data, or keep the service offline during recovery. The application cannot detect an administrator silently rewinding its serving database, control provider snapshots, or enforce physical erasure. Reopening a data-bearing backup would require a separate showing of complete deletion coverage and independent release authorization. No recovery-replay subsystem is required to quarantine and discard a backup.
